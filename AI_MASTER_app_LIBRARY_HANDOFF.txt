5. DETAILED ROOT-CAUSE ANALYSIS OF PROBLEMS ENCOUNTERED & CURRENT BLOCKERS
================================================================================

PROBLEM 1: THE 249 MB `DB_MasterHoldingTank.lua` CONSTANT-TABLE OVERFLOW (SOLVED)
--------------------------------------------------------------------------------
  * **Symptom:** `AltVault\DB_MasterHoldingTank.lua` was 249 MB on disk (containing 1,561,820 records across 648 parent addons), yet in-game Tab 6 displayed `Holding Tank: 0 Records` and fell back to scanning `1..250,000` from the WoW server (caching only 18,285 items).
  * **Root Cause:** World of Warcraft's Lua 5.1 Virtual Machine has a hard ~32 MB file compilation buffer limit and a maximum constant-table limit (`262,143` constants per function/chunk). A single 249 MB `.lua` file with 1.56 million table entries (`[1] = "...", [1561820] = "..."`) silently failed to compile in WoW's C++ Lua loader, leaving `MasterDB.HoldingTank` empty.
  * **Also Found:** `Portable_SQL_Trough\` contained both `Trough_DataRecords.tsv` (249 MB) and an empty `Trough_GameDataRecords.tsv` (0 KB); checking `File.Exists("Trough_GameDataRecords.tsv")` without checking file size caused an initial 4.58 KB empty export until fixed.
  * **Resolution:** Upgraded `Node_13_AltVaultBridge.cs` to split the 249 MB dataset into `AltVault\DB_Tank\DB_TankNode_01.lua` .. `DB_TankNode_XX.lua` (60,000 records per file) using 500-row `[[ ... ]]` multi-line raw string blocks (so 500 records count as only 1 Lua constant). `Core_MasterLootIndex.lua` unpacks those blobs on demand. **Verified Result:** Over 1,000,000+ records now load and display inside WoW in Tab 6!

PROBLEM 2: 3D DRESSING ROOM RACE & SEX SWITCHING ("WHITE BLOB" vs. PRE-PAINTED NPCS) (ACTIVE BLOCKER)
--------------------------------------------------------------------------------
  * **Goal:** The user wants to select any playable Race (`Human`, `Orc`, `Dwarf`, `Night Elf`, `Undead`, `Tauren`, `Gnome`, `Troll`, `Goblin`, `Blood Elf`, `Draenei`, `Worgen`, `Pandaren`) and Sex (`Male` or `Female`) in the Tab 6 3D Dressing Room, strip the mannequin to its base undressed racial body (`Undress()`), and `TryOn()` armor and weapons from the database—and also use this to view synced guildmates' characters in 3D when their local `.tga` videos cannot be transmitted over WoW's network sandbox.
  * **What Went Wrong in Attempt 1 (`SetCustomRace` + `SetUnit("player")`):**
    In WoW client build `16001`, calling `DressUpModel:SetCustomRace(raceID, genderID)` followed by a fallback to `SetUnit("player")` caused `SetCustomRace` to fail silently and `SetUnit("player")` to reset the model back to the user's Night Elf Female character, only changing/resetting clothing.
  * **What Went Wrong in Attempt 2 (Legacy Player Base DisplayIDs `49..60` via `SetDisplayInfo`):**
    Calling `DBTryOnModel:SetDisplayInfo(49)` (Human Male base mesh), `51` (Orc Male), etc., loaded raw unbaked geometry without a character skin shader in client `16001`, resulting in an **untextured "white blob" model**.
  * **What Went Wrong in Attempt 3 (`SetCreature(npcID)` Workaround):**
    Using NPC creature IDs (guards/trainers) via `SetCreature(npcID)` loaded textured models, **but** NPC models have pre-painted clothing baked directly into their body textures (so `Undress()` cannot strip them to underwear) and several NPC IDs did not match the intended races.
