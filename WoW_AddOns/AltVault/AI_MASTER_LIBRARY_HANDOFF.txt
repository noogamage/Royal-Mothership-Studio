A. UPGRADED MULTI-NODE HOLDING TANK ARCHITECTURE (1,000,000+ IN-GAME RECORDS)
   * Problem Solved: Previously, exporting all 1,561,820 records from the 648-addon
     vault into a single `AltVault\DB_MasterHoldingTank.lua` file produced a 249 MB
     Lua file. WoW's Lua 5.1 compiler rejected the 249 MB single-table constructor due
     to constant-table overflow (>262,143 constants), causing `MasterDB.HoldingTank`
     to load with `0 Records` in-game and forcing Tab 6 to fall back to the `1..250,000`
     live server crawler (which only cached 18,285 items).
   * Current Multi-Node Solution (`Nodes\Node_13_AltVaultBridge.cs`):
     1. `AltVault\DB_MasterHoldingTank.lua` (~4.6 KB) is now the Master Controller &
        Metadata Header. It initializes `_G.AltVaultMasterDB` (`ns.MasterDB`),
        `MasterDB.RawBlobs = {}`, `MasterDB.HoldingTank = {}`, `MasterDB.RacesAndSex`,
        `MasterDB.Classes`, and `MasterDB.Stats`.
     2. `AltVault\DB_Tank\DB_TankNode_01.lua` .. `DB_TankNode_XX.lua`: All 1,000,000+
        records are split into 60,000-record node files. Inside each node file, every
        500 records are packed into a single multi-line `[[ ... ]]` raw string literal
        (`blobs[#blobs + 1] = [[ ... ]]`), reducing Lua constant count by 500x so WoW
        loads the entire 249 MB database with zero overflow!
     3. `AltVault\Core_MasterLootIndex.lua`: `MasterDB:EnsureIndexesBuilt()` automatically
        unpacks `MasterDB.RawBlobs` line-by-line into `MasterDB.HoldingTank`, frees the
        raw blob memory, and populates `MasterDB.ByItemID`, `MasterDB.BySpellID`,
        `MasterDB.BySetID`, and `MasterDB.UniqueItemIDList`.
